# 机器人建图平台

这是一个纯 Python、无第三方运行依赖的二维建图原型。当前接入二维激光扫描和二维里程计位姿，数据模型保留 `sensor_type`、`sensor_id` 和每帧元数据，后续可在同一套运行、事件和地图版本结构中接入 IMU、轮速计或视觉特征。

## 运行演示

```bash
python -m robot_mapping.cli demo ./robot_map_project
```

演示会生成两个人工场景：

- `true_loop`：带累积里程计偏差的闭合矩形路径。候选闭环由闭环前后各多帧扫描交叉验证，接受后执行位姿图修正。
- `similar_corridors`：两段局部外观接近但连通关系不同的走廊。机器人到达第二条走廊时同时保留两个独立假设——“折叠为同一条走廊”和“确实是两条走廊”；试用折叠只生成预览地图，不改动公共地图。到达歧义点后先建立一组后续探查计划，比较去不同位置观测分别能排除哪个解释、哪些位置信息不足或两个解释无法区分；计划中的观测不算证据。实际观测到达后按来源位置和采集时刻更新假设，并记录“预期 vs 实际”的差异；首个路口观测被撤回/改派为另一条走廊时恢复受影响的方案，其他独立证据继续有效。随后在折叠分支中用一个分支探查计划走到独特凹槽位置，实际矛盾与计划预期一致并再次淘汰折叠；最终选定双走廊地图。

输出的 `DEMO_REPORT.md` 汇总操作差异，`map_versions/` 保存每个阶段的 PGM 栅格地图和位姿快照。真闭环场景还会依次生成原始漂移、接受修正、撤回修正和重新接受修正的地图版本；相似走廊场景依次生成到达时原始漂移、折叠预览、撤回后恢复对照、再次排除双走廊、重开折叠对照、新校准分支预览、部分确认作用域地图和最终双走廊等版本。

## 工程数据

- `runs/<run>/scans.jsonl`：原始二维扫描，只追加，不被闭环改写。
- `runs/<run>/poses.jsonl`：原始里程计位姿，只追加。
- `events.jsonl`：闭环提议、接受、拒绝、撤回、地图版本，假设的建立、淘汰、重开、确认事件（含保留证据），探查计划、计划执行（含预期与实际差异）、观测撤回/改派事件，以及校准版本登记、观测重解释、部分确认和校准撤回事件；从磁盘重新打开项目可完整恢复计划、实测、排除、校准分支与恢复记录。
- `map_versions/<version>/map.json`：构建该地图时使用的修正后位姿和闭环清单。
- `map_versions/<version>/map.pgm`：可直接查看的二维占据栅格地图。

## 闭环判定

粗筛使用可旋转的范围形状，解决回到原处时朝向变化的问题。真正的判定不只看一帧：系统取候选点前后扫描，对齐相邻观测，检查 ICP 误差、内点比例、多个相对位姿的平移散布和角度散布。只有多个观察相互一致时才允许接受；相似走廊可保留为拒绝记录，不会进入位姿图。

接受闭环会增加一条高权重位姿图约束并重新优化位姿，原始扫描仍保留在原文件中。撤回闭环不会删除历史，只会新增一条 `withdrawn` 事件；重新构建地图会生成新版本，旧版本仍可追溯。

## 多假设闭环

互相冲突的闭环（对同一重复地点给出不同锚点）通过 `propose_competing_closures` 各自组成独立假设，并自动附带一个“非闭环”解释。每个假设：

- 试用时只在 `build_map(..., hypothesis_id=...)` 中生成该假设下的预览地图，公共地图的已接受闭环集合不变。
- 通过 `feed_observation_to_hypotheses` 持续接收后续观测；系统沿闭环把新观测映射回锚点侧预测位置，比对范围形状距离和 ICP 内点率。最近三条证据中两条矛盾即淘汰，理由包含具体帧号与指标，且证据在淘汰后仍然保留。
- 支持 `reopen_hypothesis` 回到排除前重新比较、`eliminate_hypothesis` 再次淘汰、`confirm_hypothesis` 选定最终地图；确认时仅把该假设的闭环转为公共地图的已接受约束，竞争假设被标记淘汰。

### 成组后续探查计划

在歧义区域，系统通过 `create_probe_plan(run_id, region, target_indices, branch_hypothesis_id=...)` 把一组“打算去观测的位置”登记成一个计划，并在创建时冻结每个位置对每个假设的排除能力：

- `would_exclude_on_conflict`：折叠预测该位置对应一个已观测到的、形状独特的锚点；实际与折叠矛盾就排除该假设，实际一致则两个解释仍然并存。
- `indistinguishable`：折叠锚点是一段无特征走廊，两个解释在那里看起来一样，观测不能承诺排除任何一方。
- `insufficient_information`：折叠落到尚未观测过的锚点，排除能力未知，保留信息不足的判断。

`compare_probe_plan` 逐位置返回上述比较。计划是前瞻性的：未执行的计划不会改变任何假设的证据或状态，也不会影响公共地图。

实际观测到达后调用 `feed_observation_to_hypotheses(run_id, index, plan_id=..., source_position=..., collected_at=...)`，系统按来源位置和采集时刻评估，结论分为 `consistent`、`contradictory`、`inconclusive`（信息不足时不计入排除），并把结果与计划冻结的预测对比，把差异写入计划执行记录。`branch_hypothesis_id` 限定的计划只在该假设分支（加其对照解释）中推进。

观测被撤回或发现属于另一条走廊时调用 `withdraw_observation`：相关证据标记为 `withdrawn`/`reassigned`，依赖它而被排除的方案在剩余证据不足时自动恢复为活跃；其他观测的独立证据保持有效。原始扫描始终保留。公共地图只在 `confirm_hypothesis` 明确接受某个方案后才变化。`decision_trace(run_id)` 汇总计划、实测、排除、撤回与恢复，保存重开后仍可据此解释最终地图选择。

位姿修正只在闭环跨度（锚点与重复点之间的局部子图）内重新优化，跨度外位姿逐点等于原始里程计；撤回闭环后整个跨度恢复原样，未受影响区域始终不变。

## 按校准版本重解释探查证据

后续探查完成后，传感器校准可能被修订：同一条原始观测在旧、新校准下会对应不同位置（例如被移到相邻走廊）。系统把校准修订建模为独立的 `CalibrationVersion`，它只提供对既有原始扫描的**新解释**：

- `register_calibration(run_id, name)` 登记一个校准修订；`reinterpret_observation(calibration_id, raw_index, interpreted_index, plan_id=...)` 给出某条原始观测在新校准下的有效位置。原始观测编号、采集时刻、计划归属全部不变，也不会产生新的一帧扫描或观测；重解释先以 `proposed` 状态存在，不改动任何假设结论和公共地图。
- `compare_calibration_branches(calibration_id)` 并排比较“继续用旧校准”和“采用新校准”两个分支：逐假设给出闭环判断是否翻转、哪些原始观测的判定因此改变（旧判定 vs 新判定），以及哪些歧义在新校准下仍然存在（`ambiguity_remains`）。多个假设共享的同一条观测在每个分支中只出现一次。
- `build_map(..., hypothesis_id=..., calibration_id=...)` 只生成该校准分支的预览地图；载荷中的 `calibration_scope` 明确说明采用范围（已确认的原始观测、仅提议尚未接受的原始观测）。旧分支预览与公共地图都不会被重写。
- `confirm_calibration_interpretation(calibration_id, raw_indices)` 支持**只确认部分**观测的新解释：被确认观测的旧解释标记为 `superseded_by_calibration`，同一观测的新旧解释不会被算成两份独立支持；未确认的重解释继续留在比较分支。从该部分确认处重新打开项目（磁盘恢复）后，旧分支与尚未接受的地图保持原样。
- `withdraw_calibration(calibration_id)` 撤回后来又被撤销的校准：依赖它的判断恢复为旧校准下的结论（包括重新淘汰），依赖它的证据标记为 `calibration_withdrawn`，其他独立证据不受影响；已经构建的地图版本继续保留可查。
- `decision_trace(run_id)` 的 `calibrations` 段记录校准版本、每条重解释（原观测、解释位置、采集时刻、计划归属、确认状态）和各假设下的评估结果，使每个地图选择都能沿计划、原观测、校准版本和人工确认决定完整追溯。
